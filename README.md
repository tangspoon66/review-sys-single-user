# Review Sys · 单用户版本

面向单个场馆或活动的社交媒体素材分发系统。观众扫码打开网页，领取一条分享文案，点击复制，并长按保存活动图片；管理员通过密码登录后台管理文案和图片。

使命：降低用户分享真实到访体验的门槛，让活动内容更容易被表达和传播。

本仓库保存旧版单用户站点的独立源码，界面以深圳科学技术馆为原型。它与 [多用户版本 review-sys](https://github.com/tangspoon66/review-sys) 分开维护，不含多企业账号、活动点位、AI 生成等新版功能。

## 功能

- 板块：后台增删改名称、排序和启用状态。每个板块有稳定 ID 和专属二维码，改名或改排序不会改变链接。
- 文案库按板块分开：手工录入、UTF-8 TXT / MD / DOCX 导入、修改、删除、批量管理和同一板块内的重复内容拦截。不支持 PDF、PPTX 或旧格式 DOC。
- 图片库仍是全站一套：上传多图或文件夹、删除和批量管理。图片策略仍是关闭、随机或固定，不按板块拆图片。
- 管理员密码登录；公开页支持手机浏览器及微信内置浏览器。二维码在服务器本地生成，不会把链接发给外部服务。

## 本地启动

安装 Node.js 20.19+（建议使用 Node.js 22 LTS），然后运行：

```bash
git clone https://github.com/tangspoon66/review-sys-single-user.git
cd review-sys-single-user
npm ci
cp .env.example .env
openssl rand -base64 48
```

编辑 `.env`，设置自己的管理员账号、密码和随机会话密钥。不要直接使用示例占位值：

```dotenv
HOST=127.0.0.1
PORT=5177
ADMIN_USER=your_private_username
ADMIN_PASSWORD=your_long_unique_password
SESSION_SECRET=replace_with_the_random_value_generated_above
COOKIE_SECURE=false
```

启动服务：

```bash
npm start
```

- 观众页面：`http://127.0.0.1:5177/`
- 登录页面：`http://127.0.0.1:5177/login.html`
- 管理后台：`http://127.0.0.1:5177/admin.html`

首次启动自动创建空数据库 `data/app.db` 和上传目录。使用 `.env` 中配置的账号登录后台，先添加板块并导入文案，设置手机能够访问的站点公开地址，再下载各板块二维码。

从没有板块字段的旧库升级时，启动会清空旧文案，不会把它们放进默认板块。图片文件和图片库保留。清空条数记在 `settings.legacy_texts_cleared`。已经是板块结构的库不会再次清空。

## 使用方式与领取规则

1. 在后台添加板块（名称、排序、是否启用）。排序数字越小，后台列表越靠前；它不改变扫码链接。
2. 点选该板块后再导入文案。导入区会写明当前板块。纯文本建议每行一条完整文案；同一板块内重复内容会跳过，不同板块可以有相同文案。支持 UTF-8 TXT、MD、DOCX。
3. 需要图片时再上传，并选择关闭、随机或固定策略。图片不归属某个板块。
4. 在「站点公开地址」填写手机能够打开的 https 根地址，例如 `https://share.example.com`。不要填 localhost。留空时二维码使用你当前打开后台的地址；如果那是本机地址，页面会提示手机扫不了。
5. 每个板块可以复制专属链接、预览二维码和下载二维码。链接形如 `https://share.example.com/?s=` 加板块 ID。ID 在创建时生成，改名和改排序都不变。

观众打开没有 `s` 参数的首页时，只看到扫码提示，没有板块按钮，也拿不到文案。扫某个板块的二维码后，原页面文案区直接显示这一条，没有弹窗。只有点击复制并且复制成功，这条文案才标记为已用。只打开页面、刷新或重复预览都不会消耗。网页不能保证自动复制或直接写入系统相册。

预览会锁定这条文案大约 2 分钟，避免两个人同时拿到同一条。离开页面或超时后释放，复制成功前不会永久占用。随机图片也在复制成功时标记已用；固定图片可重复展示；关闭图片时不返回图片。

每个二维码只受自己的板块影响：

- 板块停用：提示「这个入口已停用」，不会改发其他板块。
- 链接无效或板块已删除：提示「这个入口无效」。
- 这个板块没有未使用文案：提示「次数已用完」。别的板块即使是空的，也不会挡住这个入口。

`/api/next` 不再发放文案，也不会消耗库存。文案不会自动循环；后台把文案恢复为未使用后才能再次分发。

后台列表默认返回最多 80 条，可请求到最多 200 条；它按当前板块过滤文案。二维码链接使用首页的 `/?s=` 参数，现有 Caddy 对 `/` 的白名单不用改。

## Docker 与 HTTPS 部署

本仓库的 Compose 只将应用端口绑定到服务器本机 `127.0.0.1:5177`，由宿主机 Caddy 负责 HTTPS：

```bash
cp .env.example .env
# 编辑 .env，填写真实管理员信息，并设置 COOKIE_SECURE=true
docker compose up -d --build
docker compose logs -f single-user
```

如果本机 5177 已有服务，请改 Compose 中宿主机端口，例如 `127.0.0.1:5178:5177`，并同步调整反向代理，避免影响其他项目。

**这是历史版本，服务端使用项目根目录静态服务。公网部署必须在反向代理上限制可访问路径，防止下载数据库和源码。** 宿主机 Caddy 配置示例：

```caddyfile
share.example.com {
    encode zstd gzip

    @public path / /index.html /login.html /admin.html /styles.css /script.js /favicon.ico /api/* /assets/* /uploads/images/*
    handle @public {
        reverse_proxy 127.0.0.1:5177
    }
    handle {
        respond 404
    }
}
```

域名解析到服务器后，仅开放公网 80/443，保持 5177 不对外开放。若 Caddy 在另一个 Docker 容器中，应使用独立内部网络连接应用，并将代理目标改为服务名，不要在代理容器里使用 `127.0.0.1` 指向应用。

上线前验证 `/server.js`、`/package.json`、`/data/app.db` 和 `/.env` 返回 404。旧版未包含新版完整的安全加固；长期对外提供多企业服务请使用新版。本仓库的使用说明不代表历史版本已经完成安全审计。

## 数据备份与迁移

运行数据未包含在仓库中；克隆后不会带入线上文案、管理员密码或观众领取记录。升级到板块版本时会删除旧文案表中的全部文案，见上文领取规则。

需保留 `.env`、`data/` 和 `uploads/`。停止服务后整体复制数据目录，或使用 SQLite 在线备份命令；不要只复制运行中的 `app.db` 而遗漏 WAL 日志。

```bash
sqlite3 data/app.db ".backup '/your/backup/path/app.db'"
```

还需单独备份 `uploads/`。恢复时使用同版本代码与配套数据库，不能直接与多用户版本共用数据库或上传目录。

## 修改品牌素材

- `index.html`：左上名称、右上 Logo、IP 动图。
- `styles.css`：布局、颜色与背景引用。
- `assets/`：本地品牌图片。

仓库中的场馆 Logo、IP 动图及图片仅供原项目还原参考，其权利归原权利人；其他场馆使用时应替换为有权使用的素材。

## 验证范围

旧版没有自动化测试套件，`npm test` 是原始占位命令。启动后至少检查登录、未登录访问后台、板块增删改、排序说明、当前板块是否写在导入和文案库上、两个板块二维码是否隔离、停用或无效链接是否不会领到别的板块、本板块耗尽是否只显示「次数已用完」、预览不消耗、复制成功才标记已用、二维码下载、公开地址对 localhost 的提示，以及图片上传和三种图片策略。公开二维码测试在复制成功后会消耗文案，请使用测试素材。手机真机扫码需要把站点公开地址设成手机能访问的 https 域名，不能用 localhost。
